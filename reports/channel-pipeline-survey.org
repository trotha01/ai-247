* Verdict

Pipeline base (why in brief):
- Build on our own *file contract* (job folder + =node.yaml= + =result.json=, channel = YAML graph), not a platform;
  both channels already hand off JSON files this way, so the contract outlives any orchestrator choice.
- Run it on the GPU box with *DBOS Transact* (MIT library, SQLite, no server): durable steps plus a =gpu= queue
  with a concurrency limit, which is exactly the one-card bottleneck. Huey (MIT, SQLite) is the fallback.
- Cloud steps stay *GitHub Actions* jobs exchanging job folders via R2; move to Prefect or Hatchet only for a UI or
  several boxes. Temporal and Airflow are too heavy, Arq is maintenance-only, n8n and Windmill have licence limits.
- *ComfyUI* is an =image= node behind its =/prompt= API, not the orchestrator (single box, no cloud steps, weak retries).
- *Playout stays R2 + Worker* (scales to zero); borrow ffplayout's schedule and filler model and Liquidsoap's fallback chain as ideas.
- *Agentic nodes:* dsh pinned on llama-server via its OpenAI-compatible route (with its default DeepSeek session-log
  upload turned off), opencode as fallback, the Claude Agent SDK only for nodes pinned to Claude. Pipecat later, only for a live tutor segment.

Language channel stack:
- *Text and morphology:* MACULA Greek (SBLGNT, CC BY 4.0); OSHB + MACULA Hebrew (WLC public domain, CC BY 4.0);
  Clementine Vulgate (the 1592 text is PD by age; the Tweedale edition's PD statement is 2nd-hand, verify) with
  Whitaker's Words (README grants "any and all use"). Glosses: Berean/Dodson (PD), OSHB lexicon and STEPBible (CC BY).
- *Excluded:* non-commercial sources (BHSA, PROIEL, MMS-TTS, XTTS), Nova Vulgata, and SBL Hebrew if monetized.
- *Audio:* own text-to-IPA rules per pronunciation fed as phonemes to Piper it_IT / el_GR / a community he voice;
  espeak-ng as IPA source and fallback. The he voice's CC BY 4.0 licence is 2nd-hand (Hugging Face was blocked):
  verify its model card before it airs.
- *On-screen text:* HTML/CSS cards in headless Chromium with Noto Serif Hebrew (full niqqud and te'amim), then ffmpeg.

AI-247's fact check.

* Proposed node contract (sketch)

The contract is files, not a framework API. Every orchestrator in the verdict (or a 50-line loop) can drive it, and a
node can be swapped by changing one line of the channel config. It generalises what both channels already do: the
Puddle Park producer writes =inbox/<scene>.json= atomically (=.tmp= then rename) and the worker moves it to
=done/= or =failed/=; AI-247 writes =episode/{script,plan,report}.json= and a =manifest.json= per bulletin.

** Job folder

#+begin_example
jobs/<channel>/<run_id>/<step>/            one folder per node execution
  job.json        written by the runner before start (inputs, params, node ref, attempt)
  in/             symlinks or copies of upstream outputs (read-only to the node)
  out/            everything the node produces; nothing else is read downstream
  result.json     written LAST by the node, atomically (out/... first, then result.json.tmp -> rename)
  log.txt         stdout/stderr
#+end_example

Rules:
1. A step is done when =result.json= exists with =status= in {ok, degraded}. =failed= or a missing file after the
   timeout means retry (up to =retries=) and then the channel's fallback node.
2. Nodes are pure with respect to the folder: same =job.json= + same =in/= gives an equivalent =out/=. Side effects
   (R2 PUT, D1 write, Git commit) live only in nodes of kind =publish= and must be idempotent (same key, same bytes).
3. =resources= in the node manifest is the scheduling contract: =gpu: 1= nodes on one box run through a single
   GPU lane (one queue, concurrency set per node, as channel_worker.py's =--renders 4= is today).
4. Secrets never enter =job.json=; the runner injects them as env vars only into nodes that declare them.
5. Agentic nodes (showrunner, engineer, discovery) produce proposals in =out/=; anything that runs code on air
   passes an approval node (human or automated test) first, as Puddle Park's =channel approve= does today.

** Channel config (a channel is a graph of node refs)

* Migration order (smallest first)

1. Write =nodes/*/node.yaml= and =result.json= for AI-247's existing stages without moving code; =hourly.yml= keeps
   calling them. The seam contract and =publish.py= are already shared.
2. On the GPU box, replace the =run_*.sh= loops with one DBOS (or Huey) runner that owns the =gpu= lane; MOSS
   windows become ordinary =image= jobs in that lane instead of a pause between blocks. This also gives the box the
   boot script the studio README lists as missing.
   When moving dsh to the pinned llama-server route, set =dsh-session-log-deepseek= to =enabled: false= in the
   box's =cordis.patch.yml= (it is on by default and uploads session logs with requests to the official DeepSeek
   API) and keep the OTel feedback upload off, so prompts and outputs stay on the box; confirm with a packet capture or
   the dsh debug log that no request leaves for api.deepseek.com.
3. Build the language channel on the contract from the start: corpus loader, lesson planner, gloss-check,
   pronunciation rules + Piper, HTML cards in Chromium, the shared encode and publish nodes, =PREFIX=lingua/=.
4. Only then add a =schedule= node (ffplayout-style daily JSON) if fixed-time programming is wanted.
